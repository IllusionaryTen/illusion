# Translations

Illusion ships 29 languages. The web app, the Android WebView and the Windows client all read the same catalog.

## Where strings live

- `web/i18n.mjs`
  - `languages` — the 29 locale codes and native names.
  - `english`, `extraEnglish`, `fullEnglish` — legacy blocks (kept for ordering).
  - `fullPatchEnglish` … `patch8English` — newer phrase batches.
  - `fullDetail.<code>` — per-language maps from English phrase to translation.
- Windows reads `build/translations.json`, generated by `node scripts/build-translations.mjs` (build.ps1 does this automatically).

## Adding a phrase

1. Append the English text to the newest `patchNEnglish` list.
2. Add the translation to the matching `patchN` map for every locale (a missing key silently falls back to English).
3. Run `node scripts/audit-i18n.mjs` (web) and `node scripts/audit-desktop-i18n.mjs` (Windows). Both must report zero.
4. `npm test` — the i18n test also fails when a locale is incomplete.

## Adding a language

1. Add `['xx','Native name']` to `languages`.
2. Create a full map for the code containing **every** phrase from `allEnglish` (copy an existing complete locale such as `fi` and translate).
3. Add it to `languages` ordering where it belongs.
4. `npm test`, both audits, then `npm run build` so the Windows catalog embeds the new locale.

## Rules

- Keep `Illusion` untranslated. Aura/theme names are proper nouns and stay as written.
- Numbers, `Ctrl+K`, file extensions and version strings stay as-is.
- When a word is genuinely identical in a language (e.g. Italian “Password”), add it to the allowlist in `tests/i18n.test.mjs` with a comment instead of forcing a different word.
